# 주간 매출 리포트 — 포맷 & 생성 스펙

d'Alba 미국 틱톡샵 주간 매출 리포트의 **고정 포맷**과 **데이터 소스·계산법**.
매주 자동 생성 시 이 문서를 기준으로 한다. (예: "37주차 vs 35주차")

## 주차 정의
- 한 주 = **월요일 ~ 일요일** (7일).
- 리포트는 보통 `대상주차(최근 완결 주) vs 비교주차`. 비교주차는 지정(예: 2주 전).
- 예시 주차 매핑: W35=8/24~8/30, W36=8/31~9/6, W37=9/7~9/13.
- daily-report 날짜 문자열은 `M/D` 포맷(예: `"9/7"`), 절대 `YYYY-MM-DD` 아님.

## 리포트 구조 (출력 순서)

### ■ 스토어 주차별 매출 비교
- 매출 $X (비교주차 $Y 대비 ▲/▼%) · 주문 건수(▲%) · 객단가 $ (▼/▲%)
- GMAX 광고비 $ (▼%) · GMV Max ROI (▼/▲) · 증분 ROAS Nx
- ㄴ 하락/상승 원인 한 줄 (바이럴 피크 정상화·믹스·효율 등)
- **채널별:** 동영상 / 프로덕트카드 / 브랜드라이브(셀러라이브) / AF라이브 / 공식계정매출(셀러영상) — 각 $ 와 WoW%
- **채널별 객단가:** channelAov 기준 — 특히 브랜드라이브가 객단가 최고인 경우가 많음(라이브=세트·다개 구매). 라이브 성장이 매출뿐 아니라 객단가에도 기여하는지 한 줄.
- **🔦 라이브 스팟라이트:** 브랜드라이브·AF라이브가 오른/내린 이유 (어느 날·어느 제품·어느 크리에이터가 견인했는지 일별/제품별로 근거 제시)

### ■ 제품별 매출 비교 (7개 블록)
각 제품:
- 매출 $ (비교주차 $, ▲/▼%) + 상태 이모지(🟢성장/🔴하락)
- 방문 →(▼/▲%), 광고비 →(▲/▼%), ROI →, CVR →(▲/▼%p), **객단가 $→$(▲/▼)**, (증분 ROAS N — 광고비 유의미 변동 시만)
- ㄴ **채널별:** 주요 증감 채널 (동영상/AF라이브/프카/셀러영상/셀러라이브 중 움직인 것) — **절대 빠뜨리지 말 것**
- ㄴ 매출 증감 원인 (전환율·트래픽·소재·재고·크리에이터 등 실제 원인)
- ㄴ **객단가↔전환율 연결:** 객단가와 CVR을 함께 해석한다. 객단가가 오르면 전환율이 떨어질 수 있고(가격저항), 저가 단품 위주 유입은 객단가↓+전환 왜곡을 부른다. CVR이 움직였으면 객단가 변화가 원인인지 반드시 점검.
- ㄴ 영상 발행 건수 →, 샘플 시딩 →
- ㄴ [이번 주 발행 TOP3] — 크리에이터·발행일·$·**영상 링크** (3개 전부)
- ㄴ [기존 발행 TOP3] — 크리에이터·발행일·$·**영상 링크** (3개 전부)

### 💡 추가 인사이트 (5개 내외)
재고 상한 / 크리에이터 집중·의존 리스크 / 라이브 방어 / 샘플 시딩 확대 / 전환율 추세 등.

### ✅ 차주 액션
제품별·채널별 구체 액션 (재고 회복 재점화, 라이브 확대, 소재 다변화 등).

## 데이터 소스 & 계산법

전부 배포된 API에서 뽑는다. 프로덕션: `https://project-zizml.vercel.app`.

### 공통: 캐시 우회 필수
GET 응답이 CDN 캐시될 수 있으므로 **항상 캐시버스터**를 붙인다: `&cb=<timestamp>`.
안 붙이면 오래된(비어있는) 데이터가 올 수 있음.

### AF 탭 선행 조건 ⚠️
무가/유가(org/shop)·영상 Content ID(링크)는 **AF 탭이 채워져야** 나온다.
- daily-report를 `date=<주 마지막날>`로 부른 뒤, 대상주 각 날짜의 `series` org/shop 이 0이 아닌지, `revVideos[].cid` 가 채워졌는지 확인.
- 비어 있으면 AF 탭(주문별 AF 매출 RAW)의 **오가닉/샵애즈 컬럼 + Content ID(O열)** 미입력 상태 → 사용자에게 채워달라고 요청.
- 과거 이슈: O열(Content ID)이 한 칸 밀려 P열로 들어가면 cid·org/shop 파싱이 깨짐.

### 스토어 총계 (권위값)
`GET /api/daily-report?format=json&date=<주 마지막날>&cb=…` → `weekly` 배열.
각 원소 `{label:"8/24~", gmv, orders, spend, roi}`. 대상주/비교주 label로 매칭.
- 매출=gmv, 주문=orders, 광고비=spend, ROI=roi(=GMV Max ROI)
- 객단가 = gmv/orders
- **증분 ROAS = (비교주 gmv − 대상주 gmv) / (비교주 spend − 대상주 spend)** = ΔGMV/ΔSpend (WoW). "줄인/늘린 광고 $1당 매출 $N".

### 채널별 (스토어 & 제품)
- 스토어: 각 날짜 daily-report의 top-level `channels[]` (`{name, gmv}`)를 **주간 합산**. 대상주는 7일 각각 fetch해서 합산, 비교주도 동일.
- 제품별: 각 제품 `products[].channels[]` (`{name, v}`)를 주간 합산.
- 채널명 매핑: `Affiliate Video`=동영상, `Affiliate LIVE`=AF라이브, `Product Card`=프로덕트카드, `Seller Video`=공식계정매출(셀러영상), `Seller LIVE`=브랜드라이브(셀러라이브).

### 라이브 스팟라이트
- 브랜드라이브: 각 날짜 스토어 `channels` 의 `Seller LIVE` gmv를 **일별로** 뽑아 어느 날 스파이크였는지 찾음.
- AF라이브: 일별 `Affiliate LIVE` + **제품별 Affiliate LIVE**(`products[].channels`)로 어느 제품이 견인했는지 귀속.

### 제품별 지표 (방문/전환/객단가)
`products[].series[]` (필드: date, gmv, orders, cost, roi, uclk, org, shop, newVid, samples…)를 대상주/비교주 날짜로 합산.
- 방문 = Σ uclk, 광고비 = Σ cost, ROI = Σgmv/Σcost
- CVR = Σorders/Σuclk × 100, 객단가(AOV) = Σgmv/Σorders (제품 aov 필드와 동일 공식의 주간판)
- 신규영상 = Σ newVid, 샘플 = Σ samples
- 채널별 객단가는 top-level `channelAov` (전체/Seller LIVE/Seller Video/크리에이터/Product Card) 사용.
- 객단가↔전환율: 두 지표를 반드시 함께 해석 — 객단가 상승이 CVR 하락의 원인(가격저항)일 수 있고, 저가 단품 유입은 객단가↓·CVR 왜곡을 만듦.
- 증분 ROAS = ΔGMV/ΔSpend (광고비 변동이 유의미할 때만; 거의 동일하면 "해당없음")
- 퍼스트는 본품+세트 두 PID 합산, 블록 안에 SKU 분해도 표기.

### 발행 영상 TOP3 (이번 주 / 기존)
1. 대상주 **7일 각각** `date=YYYY-MM-DD&format=json&cb=…` fetch (revVideos는 target-day 기준).
2. 제품 PID들의 `revVideos[]`를 **cid로 주간 합산**: `{creator, cid, pay 합}`.
3. **발행일 = cid에서 디코딩:** `new Date(Number(BigInt(cid) >> 32n) * 1000)` (TikTok 영상 ID 상위 32비트 = 생성 unix초).
4. **이번 주 발행** = 발행일이 대상주 범위 내, **기존 발행** = 그 이전.
5. 각 그룹 pay 상위 TOP3, **링크 = `https://www.tiktok.com/@{creator}/video/{cid}`** (cid 있으면 항상 생성).
- (무가/유가 라벨은 붙이지 않는다 — 요청으로 제거됨.)

### 참고
- 소재별 실제 광고지출·판정(BOOST/KILL)까지 붙이려면 `/api/ads-report`(광고 소재 시트, 비밀번호 필요) 를 추가로 조인. 기본 주간 리포트엔 미포함.
- 스토어 방문자 총계는 daily-report에 주간 필드가 없어, 주요 제품 series uclk 합(롱테일 제외)으로 근사 표기.

## 자동화 메모
매주 자동 생성 시: 위 fetch(주 마지막날 daily-report + 대상주 7일 daily-report + 비교주 7일)를 모아
스토어/채널/라이브/제품 블록을 조립하는 스크립트 또는 엔드포인트로 구현.
AF 미충족(org/shop·cid 비어있음)이면 리포트 생성 대신 "AF 탭 <날짜> 채워달라" 경고.
